# pedigreegraph
Family health tracker: a graph-based agent that follows family trees in FalkorDB to flag inherited risk, with exact genetics for single-gene conditions.
# PedigreeGraph: a family health tracker on FalkorDB

**Hackathon:** Graph Hacks: Context for AI Agents (FalkorDB x WeMakeDevs)
**Track entered:** Track 01, Agents That Act on Connected Data
**Entry:** solo

> **All data is synthetic.** The families are generated by `generate_families.py`. The condition names are real
> (beta-thalassemia, familial hypercholesterolemia, sickle cell disease), but only the *inheritance pattern* is modelled.
> This is family-history risk awareness, **not a diagnosis or medical advice.**

## What it does

A person's family tree is a graph. PedigreeGraph stores synthetic families in FalkorDB and gives an AI agent graph tools
to answer questions like:

- *What is the risk picture for FAM1_P14?*
- *Which family looks dominant, and which couples should worry?*
- *Who should be tested first in FAM3?*

For each answer the agent reports the condition, the person's chance of being a carrier (or of having inherited the allele),
the chance a future child of a couple is affected, the shared ancestors behind a risk (consanguinity), the **family path**
that supports each point, and cautious next steps ("discuss with a doctor or genetic counselor"). The web page draws the
pedigree and highlights the path the agent used.

The LLM never calculates risk. It chooses tools and explains; the numbers come from deterministic code.

## Architecture

```
FalkorDB (graph "pedigree")  <--Cypher--  pedigree_tools.py / agent_tools.py  <--tool calls--  Gemini agent
                                                                                      |
                                                              app.py (Flask page: pedigree drawing + chat + path highlight)
```

| File | Role |
|---|---|
| `generate_families.py` | Builds 3 synthetic 4-generation families with a planted condition and loads them into FalkorDB. Writes hidden truth to `ground_truth.json` (not committed) so results can be checked. |
| `pedigree_tools.py` | Graph tools (Cypher) and the exact inference engine. |
| `agent_tools.py` | The 8 tools exposed to the agent, including `health_report(person)`. |
| `agent_gemini.py` | Gemini agent in the terminal (automatic function calling). |
| `app.py` | Flask web UI: family tree, chat, red highlight of the agent's family path. |

## Graph data model

```
(:Person {id, family, condition, sex, generation, affected, tested})
(:Person)-[:PARENT_OF]->(:Person)      // parent -> child
(:Person)-[:PARTNER_OF]->(:Person)     // father -> mother
```

Index: `CREATE INDEX FOR (p:Person) ON (p.id)`. Each family is a separate connected cluster of the graph.
The graph stores only what a counselor could observe (relationships, sex, generation, affected or not). True genotypes and the
inheritance mode are kept outside the graph so the agent cannot "cheat".

## Cypher queries the product depends on

Load a family into the agent's working context:
```cypher
MATCH (p:Person {family:$fam}) RETURN p.id, p.sex, p.generation, p.affected, p.tested, p.condition
MATCH (a:Person {family:$fam})-[:PARENT_OF]->(b:Person) RETURN a.id, b.id
MATCH (a:Person {family:$fam})-[:PARTNER_OF]->(b:Person) RETURN a.id, b.id
```

Obligate carriers (graph pattern tool): unaffected parents of an affected child must carry a recessive allele.
```cypher
MATCH (par:Person {family:$fam})-[:PARENT_OF]->(c:Person {family:$fam, affected:true})
WHERE NOT par.affected
RETURN par.id, collect(c.id)
```

Consanguinity (multi-hop graph tool): partners who share an ancestor within 3 generations.
```cypher
MATCH (a:Person {family:$fam})-[:PARTNER_OF]->(b:Person {family:$fam}),
      (anc:Person)-[:PARENT_OF*1..3]->(a),
      (anc)-[:PARENT_OF*1..3]->(b)
RETURN a.id, b.id, collect(DISTINCT anc.id)
```

Which family does a person belong to (used by `health_report`):
```cypher
MATCH (p:Person {id:$id}) RETURN p.family
```

Bulk load (generator):
```cypher
UNWIND $rows AS r CREATE (:Person {id: r.id, family: r.family, condition: r.condition, sex: r.sex,
                                   generation: r.generation, affected: r.affected, tested: false})
UNWIND $rows AS r MATCH (a:Person {id: r.a}), (b:Person {id: r.b}) CREATE (a)-[:PARENT_OF]->(b)
UNWIND $rows AS r MATCH (a:Person {id: r.a}), (b:Person {id: r.b}) CREATE (a)-[:PARTNER_OF]->(b)
```

## How the graph is used, and a known limitation

The graph is the system of record: every answer starts from relationships read out of FalkorDB, two tools are pure graph
pattern queries (obligate carriers, consanguinity), and the agent's explanation is a path through the pedigree.

**Limitation (honest note):** the Mendelian probability calculation runs in Python over the family structure retrieved from
FalkorDB, rather than inside the database.

## Inference method

For a family, the engine computes the exact posterior over every member's genotype (0, 1 or 2 disease alleles) given who is
affected, by enumerating genotype assignments through the pedigree with Mendelian transmission. Because each person is one
variable, a shared ancestor is counted correctly (consanguinity is not underestimated). It is used to:

- compare recessive vs dominant explanations (`infer_inheritance`),
- compute each unaffected person's carrier risk (`relative_risks`),
- compute the chance a future child of a couple is affected (`couple_risks`).

**Assumptions:** single gene, complete penetrance, no new mutations, assumed population allele frequency (recessive 1%,
dominant 0.1%). X-linked inheritance, age of onset and common multifactorial conditions are not modelled.

## Setup (Windows PowerShell)

Requires Docker Desktop and Python 3.10+.

```powershell
# 1. Start FalkorDB (data persists in a Docker volume; browser UI on http://localhost:3000)
docker run -d --name falkordb -p 6379:6379 -p 3000:3000 -v falkordb_data:/var/lib/falkordb/data falkordb/falkordb:latest

# 2. Install dependencies
pip install -r requirements.txt

# 3. Generate and load the synthetic families
python generate_families.py

# 4. Check the graph tools (optional)
python pedigree_tools.py

# 5. Set your Gemini API key (never commit it) and start the web UI
$env:GEMINI_API_KEY = "your-key"
# if you get a "model not found" error, set a current model name:
# $env:GEMINI_MODEL = "gemini-3.8-flash"
python app.py        # open http://localhost:5000
```

Terminal agent instead of the web page: `python agent_gemini.py`.

## Configuration (environment variables)

| Variable | Purpose | Default |
|---|---|---|
| `FALKORDB_HOST`, `FALKORDB_PORT` | FalkorDB endpoint | `localhost`, `6379` |
| `FALKORDB_USER`, `FALKORDB_PASSWORD` | FalkorDB Cloud credentials | none (local Docker needs none) |
| `FALKORDB_SSL` | `true` if your instance uses TLS (the Cloud Free tier has none) | off |
| `GEMINI_API_KEY` | AI chat. Without it, clicking a person on the tree still shows their report | none |
| `GEMINI_MODEL` | Gemini model name | `gemini-3.8-flash` |
| `ASK_PER_HOUR`, `ASK_PER_DAY` | Question limits per visitor / for the whole demo (for a public deployment) | effectively off |

## Live demo / deployment

**Live demo:** [https://pedigreegraph.onrender.com/]  (free tier: the first load after idle can take about a minute)

The live version runs the Flask app on Render with the graph hosted on FalkorDB Cloud. Clicking a person on the tree gives an
instant report from the graph queries and the exact genetics (no AI call); the chat uses Gemini and is rate limited.
If the live link is down, follow the local setup above.

Deploying yourself: create a Render Web Service from this repo with build command `pip install -r requirements.txt` and start
command `gunicorn app:app --workers 1 --threads 4 --timeout 120 --bind 0.0.0.0:$PORT`, set the environment variables above,
and load the data once with `python generate_families.py` pointed at your FalkorDB Cloud instance.

("higher chance", "discuss with a doctor") and never to state that someone will or will not develop a condition.
